# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal blog/website for Anssi Piirainen (anssipiirainen.com), built with Eleventy (11ty) v3 alpha + Tailwind CSS. The site is statically generated and deployed to S3 + CloudFront via GitHub Actions on push to `main`.

## Commands

Use `pnpm` for all package management and script running (a `pnpm-lock.yaml` is committed).

- `pnpm install` — Install dependencies.
- `pnpm dev` — Runs Tailwind in watch mode and Eleventy with `--serve --watch` in parallel (BrowserSync auto-opens).
- `pnpm go!` — Full clean build: clean → favicon generation (`icon`) → CSS → Eleventy → social images. Use when icons/favicons need regenerating.
- `pnpm build:ci` — Production build used in CI/Netlify (skips icon regeneration). Note: `AWS_LAMBDA_FUNCTION_NAME=trickpuppeteer` is set in CI to coerce `pwa-asset-generator`/Puppeteer to run in a Lambda-like mode.
- `pnpm clean` — Wipes `public/`.

There is no test suite, linter, or formatter configured.

## Architecture

### Build pipeline (11ty + Tailwind + social images)

Eleventy is configured by `.eleventy.js`. Key points:

- **Input/output directories are overridden**: input is `./src/`, output is `./public/`, with includes/layouts/data under `src/_11ty/` (`_includes/`, `_layouts/`, `_data/`). The unusual `/_11ty/_includes/` etc. paths (with leading slash) in `dir` config are relative to the input dir.
- **Passthrough copies** map `src/_11ty/_static/{app,favicon,img,js}` and `src/images` to the site root — content under `_11ty/_static/app/` is copied to `/`.
- **Custom shortcodes**: `{% image src, alt, sizes, classes %}` (in `src/_11ty/shortcodes/image.js`) uses `@11ty/eleventy-img` to generate responsive AVIF/WebP/JPEG/PNG variants into `public/img/`. `{% year %}` outputs the current year.
- **HTML minification** runs as a transform on all `.html` outputs.
- **Custom collection `visiblePosts`**: posts tagged `post` with `hidden !== true` — use this in templates rather than the raw `post` collection if filtering hidden drafts.

### Content model

Blog posts live in `src/post/*.md` with frontmatter shape:

```yaml
title: ...
description: ...
date: YYYY-MM-DD
published: true        # not auto-enforced; filtering uses `hidden`
hidden: true           # excludes from visiblePosts collection
tags: ["post", ...]    # must include "post" to surface in the blog
layout: article.njk
permalink: "/post/{{ title | slug }}.html"
```

Layouts in `src/_11ty/_layouts/`: `article.njk` (posts), `blog.njk` (post index), `page.njk` (static pages like `index.md`, `blog.md`).

### Styling

Tailwind is run twice with different entry CSS:
- `src/_11ty/_tailwindCSS/raw-website.css` → `public/css/style.css` (the site's stylesheet).
- `src/_11ty/_tailwindCSS/raw-social.css` → `src/_11ty/_social/social.css` (consumed by social-image generation).

`tailwind.config.js` is the single source for theme/typography customization across both.

### Social image generation

`@11tyrocks/eleventy-plugin-social-images` reads `src/_11ty/_social/pages.json` (generated by `src/_11ty/_generate/pagesjson.njk` from the `visiblePosts` collection) and renders `template.html` + `social.css` into PNGs under `public/img/social/`. This step runs *after* Eleventy in `go!` / `build:ci` because it needs the generated `pages.json` to exist in `src/`.

Site-wide metadata (author, social handles, theme color, URL) is centralized in `src/_11ty/_data/meta.js` and surfaced as `meta.*` in templates.

### Deployment

`.github/workflows/deploy.yml` runs on push to `main`: builds via `npm run build:ci`, then `aws s3 sync ./public/ s3://anssipiirainen.com --delete --acl public-read` and a CloudFront invalidation. `netlify.toml` exists as an alternate deploy target but S3 is the live one.
